# Серверные транспортные модели

`mise run install` восстанавливает этот изолированный набор через `npm ci`.
`mise run generate` генерирует OpenAPI, SDK и серверные артефакты из одного
`contract/main.tsp`. `mise run generate:check` проверяет их актуальность;
серверная проверка сравнивает полное содержимое каталогов, включая лишние
неотслеживаемые файлы, без изменения проверяемых артефактов.

Здесь зафиксированы emitter `0.58.0-alpha.32`, compiler/http/json-schema/openapi
`1.17.0`, rest/versioning `0.86.0`; lock-файл также фиксирует emitter-framework
`0.21.0`, Alloy core `0.24.1` и csharp `0.24.0`. Это отдельный npm-проект,
не workspace frontend: версии библиотек клиентской генерации не меняются.

Перед каждым запуском `patch-emitter.mjs` явно проверяет версию и SHA-256
полных исходников emitter и применяет три исправления из #56: required для
обязательных свойств без инициализатора, nullable для необязательных и DateOnly
для plainDate. Повторное применение безопасно. Несовместимый исходник или версия
останавливают процесс до изменения файлов патча. Это проектный патч источника,
а не поддержка этих возможностей официальным непатченным релизом.

Каталог `backend/BookingCalendar.Api/Generated` целиком принадлежит генератору:
его нельзя редактировать вручную или использовать для рукописного кода.
Генерация сначала работает в `artifacts/server-generation`, затем копирует
модели и helpers; устаревшие выходы удаляются. MVC, operations, Program и
HttpServiceException не копируются. Компиляция явно включает только Models и Lib.
HTTP возвращает тела моделей; response-обёртки не следует сериализовать.
Domain и Application от generated-моделей не зависят.

При обновлении сначала проверить upstream-исправления и ADR-0003, затем изменить
точные версии и lock-файл, заново обосновать патч и его контрольные суммы по
исходникам официального пакета. Чистая установка, повторная генерация, негативные
проверки патча и актуальности, HTTP-conformance и полный `mise run check` должны
пройти до публикации. Эксперимент в docs не участвует в этой цепочке.

Проверка #60 от 2026-11-07: первый запуск
`mise exec -- node --test scripts/server-generation.test.mjs` завершился красным
из-за отсутствующей production-команды. После реализации оба теста зелёные:
изменённый, удалённый и лишний выход дают отказ `--check`, содержимое при проверке
сохраняется; генерация восстанавливает актуальные выходы. Отдельный тест проверяет
повторный патч и отказы на alpha.33 и повреждённый исходник. Зелёные также
`mise run test` (84 теста, включая HTTP health по OpenAPI), `test:scripts`
(10 тестов), `build:dotnet` (0 предупреждений), `lint:dotnet`, `lint:docs`, `knip`.
Общий check и CI проверяются на итоговой интеграционной ветке перед публикацией.

Проверка #61 от 2026-11-07: перевод проверки ошибок на полные схемы операций
с фактическим статусом дал красный результат: 12 из 84 HTTP-тестов упали с
`RefResolutionException` на ссылках внутри `anyOf`. После рекурсивного раскрытия
альтернатив все 84 исходных теста зелёные. Создание и список типов встречи теперь
используют generated request/MeetingType, общие ошибки — generated ProblemDetails.
Ручной разбор сохраняет прежние ошибки обязательных полей вместо ошибок binder.
Дополнительные HTTP-проверки сопоставляют request-схему и ответы на пропущенные поля,
null и неверные JSON-типы, принимают лишние поля, проверяют непустой список,
метаданные и отсутствие errors у ошибок без полей. Отрицательные примеры отвергают
неизвестный enum, нестроковые сообщения errors и HTTP-обёртки; включена проверка
форматов. Общий check и CI выполняются на итоговой интеграционной ветке.
